## Design and boundaries

Follow the Notes API request through gateway routing, common policies and backend work. Teach identity and resource authorization, trusted identity propagation, distributed traffic limits, failure budgets and retry responsibility, and when an extra gateway earns its cost. The independent contract freezes card order and transfer criteria before authoring. Reuse the existing dialog and styles; expose the deck only for normalized API Gateway network components. No gateway implementation, simulator, new dependencies or evaluator redesign.

Choose direct lesson/diagram registration over a new framework. Two small diagrams explain the request path and policy boundaries. Keep current compact reports in Git and raw eval/browser proof outside it. The user's retention question did not authorize deleting existing archives or changing retention policy.

Ruling: preserve the conservative shared-renderer hash for this task. Registration changes invalidate caching, queues and load-balancing evidence; refresh with fresh sessions, never relabel old hashes. This adds evaluation work but avoids combining an evaluator redesign with new content.
